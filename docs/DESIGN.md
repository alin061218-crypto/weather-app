## 0. 为什么要有这份文档

这个项目一路反复出现同一类问题：**两套体系并存、定义了不用的令牌、写死的数值、
样式出现在两个地方、骨架屏与真实组件不一致**。逐条看都是小问题，**根因只有一个：
规则没有被写下来**。写下来的规则才能被检查、被引用、被违反时指出。

本文每条规则都分成两类，写清楚区别：

- **`[约束]`** —— 有客观依据（对比度、可测量、有实证反例）。**必须遵守，可脚本断言。**
- **`[决策]`** —— 设计方的取舍，没有对错，但**改了要说明理由**并更新本文。

## 1. 设计原则

三个词：**静谧 · 自然 · 精致**（取自 `PRODUCT.md`）。

| 原则     | 具体含义                               | 反面                         |
| -------- | -------------------------------------- | ---------------------------- |
| **静谧** | 不乱、不吵、不堆砌；信息密度高但不嘈杂 | 满屏色块、每个区块都要"抢眼" |
| **自然** | 像大自然本身，不是科技感/科幻感        | 发光边框、霓虹渐变、HUD 风格 |
| **精致** | 细节见工艺；对齐、间距、发丝线都要对   | 随手写死的 4px/7px 混用      |

**反例（anti-references，`PRODUCT.md` 明列）**：科技感仪表盘、赛博朋克、渐变玻璃拟态。

**一条贯穿性判断**：信息密集 ≠ 视觉嘈杂。做法是**靠排版层级与发丝线组织**，
不靠卡片、色块、阴影堆叠。见 §6。

## 2. 色彩系统

### 2.1 基础令牌

代码位置：`frontend/css/style.css` 的 `:root`（暗色）与 `[data-theme="light"]`（亮色）。

| 用途               | 暗色（默认）            | 亮色                    | 说明                   |
| ------------------ | ----------------------- | ----------------------- | ---------------------- |
| `--bg`             | `#0a0e17`               | `#f6f4f0`               | 页面底                 |
| `--surface`        | `#121724`               | `#eeebe6`               | 一般表面               |
| `--surface-raised` | `#1a2030`               | `#e8e4de`               | 上浮一层               |
| `--surface-hover`  | `#1f2638`               | `#e0dbd4`               | 悬停                   |
| `--surface-card`   | `#161c2a`               | `#ebe7e1`               | 卡片/面板              |
| `--surface-active` | `#232b40`               | `#ddd7cf`               | 按下                   |
| `--surface-glass`  | `rgba(18,23,36,.78)`    | `rgba(246,244,240,.82)` | 玻璃层                 |
| `--ink`            | `#e8ecf2`               | `#1a1d24`               | 正文                   |
| `--ink-secondary`  | `#9aa4b8`               | `#5c6270`               | 次级                   |
| `--ink-muted`      | `#8b95a8`               | `#5b6472`               | 弱化                   |
| `--primary`        | `#5b9cf5`               | `#2c6ccf`               | 品牌色（天青蓝）       |
| `--primary-hover`  | `#73adf7`               | `#2c6ccf`               | 悬停                   |
| `--primary-on`     | `#08101c`               | `#ffffff`               | **品牌色底上的文字色** |
| `--accent`         | `#f0a050`               | `#d88a3a`               | 强调（暖琥珀）         |
| `--danger`         | `#e06070`               | `#c83040`               | 危险                   |
| `--border`         | `rgba(255,255,255,.06)` | `rgba(0,0,0,.06)`       | 发丝线                 |
| `--border-strong`  | `rgba(255,255,255,.10)` | `rgba(0,0,0,.12)`       | 强分隔                 |
| `--border-active`  | `rgba(255,255,255,.16)` | `rgba(0,0,0,.16)`       | 按下/聚焦边界          |

**`[约束]` 品牌色上的文字必须用 `--primary-on`，不得硬写 `#fff`。**
依据：白字在暗色 `--primary`（`#5b9cf5`）上只有 **2.79:1**，hover 时 **2.32:1**，
**均不达 AA**；改用 `--primary-on` 后为 **6.83:1 / 8.22:1**。亮色下白字为 5.06:1。

**`[约束]` 亮色主题下 `--primary-hover` 与 `--primary` 同值。**
依据：亮色 `#2c6ccf` 再亮就掉出 4.5:1；因此亮色下"悬停"靠**表面色变化**表达，不靠加深品牌色。

### 2.2 场景体系（7 个天气场景 / 8 条规则）

界面不是单一底色 —— 有 **7 个天气场景**，其中 `clear` 分昼夜两种变体，
因此 CSS 里共 **8 条** `body[data-weather="…"]` 规则。每套定义 `--scene-bg` / `--scene-ink` /
`--scene-secondary` / `--scene-muted` / `--scrim-text`，挂在 `body[data-weather="…"]`。

| 场景          | `--scene-bg` | `--scene-ink` | `--scene-secondary` | `--scene-muted` |
| ------------- | ------------ | ------------- | ------------------- | --------------- |
| `clear-day`   | `#182334`    | `#f3f6fa`     | `#c3cbd8`           | `#a9b4c5`       |
| `clear-night` | `#0a0e17`    | `#eef3fa`     | `#c3cbd8`           | `#a9b4c5`       |
| `cloudy`      | `#172233`    | `#eef2f7`     | `#c3cbd8`           | `#a9b4c5`       |
| `overcast`    | `#151f2e`    | `#eef2f7`     | `#c3cbd8`           | `#a9b4c5`       |
| `rain`        | `#101c2e`    | `#eef2f7`     | `#c3cbd8`           | `#a9b4c5`       |
| `snow`        | `#2b3648`    | `#f2f5f9`     | `#d1d8e2`           | `#b4becd`       |
| `fog`         | `#262e3a`    | `#f2f5f9`     | `#d1d8e2`           | `#b4becd`       |
| `storm`       | `#111827`    | `#f2f5f9`     | `#cfd7e2`           | `#b1bdcd`       |

**`[约束]` 亮色主题只允许一条场景规则**：`[data-theme="light"] body[data-weather] { … }`
统一覆盖为 `bg #f6f4f0 / ink #1a1d24 / secondary #3f4a5c / muted #596476`。

> **依据（实证）**：曾经存在一条例外 —— 亮色主题下 `clear-night` 保留深色背景 `#243047`。
> 结果是「**浅色卡片浮在深色夜空上**」，作者实测后投诉。已删除。
> **规则：亮色主题就是全站亮色，深色主题就是全站深色。不允许跨主题混用。**

**`[约束]` `--scene-muted` 必须逐场景定义。**
依据：`--ink-muted` 映射到 `--scene-muted`；若某场景未定义，`var()` 会解析成无效值，
所有弱化文字退化为继承色。**每个场景都必须有，禁止只定义其中几个。**
（早前 `snow` 场景缺失导致对比度降到 4.04:1。）

### 2.3 对比度底线

**`[约束]` 全部 7 个场景 × 深色/亮色两套主题：**

| 角色                   | 最低要求 | 实测最低值                          |
| ---------------------- | -------- | ----------------------------------- |
| 正文 `--ink`           | ≥ 4.5:1  | 15.35:1（亮色）                     |
| 次级 `--ink-secondary` | ≥ 4.5:1  | 8.15:1（亮色）                      |
| 弱化 `--ink-muted`     | ≥ 4.5:1  | **5.45:1**（亮色，全局最低）        |
| 焦点环 `--primary`     | ≥ 3:1    | 3.99:1（亮色）/ 4.36:1（暗色 snow） |

**验证方式**：脚本计算，**不接受目测**。见 `evidence/TASK-015e/contrast.txt`、`evidence/TASK-019/contrast.txt`。

> ### ⚠️ 已知缺口（2026-10-04 核验时发现，待修）
>
> `evidence/TASK-019/contrast.cjs:7` 的场景列表是**写死的 7 个**：
>
> ```js
> const scenes = ['clear-day', 'clear-night', 'cloudy', 'rain', 'snow', 'fog', 'storm'];
> ```
>
> **漏了 `overcast`** —— 而 `:59` 打印 `PASS: ${scenes.length} scenes`，
> 读起来像"全部场景都验过了"。
>

> 但这是**方法学缺陷**：一份声称覆盖全部场景的测试，实际漏了一个，且**看不出来**。
>
> **正确做法（不要只补一个字符串）**：**从 `style.css` 派生场景列表** ——
> 解析所有 `body[data-weather="…"]` 选择器，逐个验证。这样以后新增场景会自动被覆盖。
> 这与 §8 反模式 #4 是同一条规则：**不要写死派生数量**。

### 2.4 温度色标

**`[约束]` 温度色标必须用固定绝对刻度，不使用相对归一化。**

来源：**QX/T 180—2013《气象服务图形产品色域》4.1.1**（中国气象局，现行有效）。
≥0℃ 用暖色（红→薇）、<0℃ 用冷色（薇→紫），**冷色走长弧**。

代码位置：`frontend/js/visuals.js` 的 `STD_SCALE`（15 个锚点，每 5℃ 一个）：

| 温度 | 颜色      | 温度  | 颜色          | 温度 | 颜色      |
| ---- | --------- | ----- | ------------- | ---- | --------- |
| −30  | `#80419d` | −10   | `#00e4c5`     | 10   | `#ffcf00` |
| −25  | `#6968d3` | −5    | `#6cf987`     | 15   | `#ffb500` |
| −20  | `#0694f0` | **0** | **`#efff2d`** | 20   | `#ff9a00` |
| −15  | `#00c0ea` | 5     | `#fde700`     | 25   | `#ff7e00` |
|      |           |       |               | 30   | `#ff6100` |
|      |           |       |               | 35   | `#ff4100` |
|      |           |       |               | 40   | `#fe130c` |

**`[约束]` 超出 −30 / 40 时**取端点色（`tempColor()` 已实现），**不得外推**。

**`[决策]` 插值方式**：锚点之间用**线性 RGB 插值**（`visuals.js:18-20`）。

> 原设计意图是 OKLCH 插值。锚点间距只有 5℃，线性 RGB 与 OKLCH 的差异很小；
> **"长弧"是靠 15 个锚点本身编码的，不依赖插值空间**，所以视觉结论不受影响。
> 若日后要提升平滑度，只改插值函数即可，锚点不变。

**`[决策]` 温度色标只用于"温度直方/指纹"，不用于文字或品牌元素** —— 避免与 `--primary` 抢位置。

## 3. 排版角色

**`[约束]` 只允许 5 (+1) 个文字角色，全部用 `--type-*`；不允许在组件里现写字号字重组合。**

| 角色              | 定义                                       | 用在哪                   |
| ----------------- | ------------------------------------------ | ------------------------ |
| `--type-display`  | `700 5.5rem / 1.02` + 字距 `-0.03em`       | 英雄区大温度             |
| `--type-headline` | `600 var(--text-xl) / 1.25`                | 城市名、区块标题         |
| `--type-data`     | `600 var(--text-base) / 1.2`               | 指标数值、7 天温度       |
| `--type-label`    | `500 var(--text-sm) / 1.5`                 | 指标标签、日期、chip     |
| `--type-copy`     | `400 var(--text-base) / 1.7`               | 建议正文、指南正文       |
| `--type-eyebrow`  | `600 var(--text-xs) / 1.4` + 字距 `0.16em` | 小标题（如"江苏，中国"） |

**字号阶梯**（比例 1.2）：`--text-xs` .688rem ｜ `--text-sm` .813rem ｜ `--text-base` .938rem ｜
`--text-lg` 1.125rem ｜ `--text-xl` 1.375rem。

**`[约束]` 最小字号 `--text-xs`（11px）**。除 `--type-eyebrow` 用途外不得再小。
（历史问题：`.tab-btn-label` 曾用 10px，是全站最小。）

**`[约束]` 仪表数值、图表轴、温度数字必须 `font-variant-numeric: tabular-nums`** ——
否则数字宽度不齐，读数跳动。

**`[决策]` 单一无衬线字体，不引入衬线体、不引入 Web Font。**
字体栈：`system-ui, -apple-system, "PingFang SC", "Noto Sans SC", "Microsoft YaHei", sans-serif`。
理由：中文 Web Font 体积大；系统字体在各平台都是最优渲染。

## 4. 间距 · 圆角 · 动效 · 层级

### 4.1 间距

**`[约束]` 只用 4px 基准的 9 档 + 3 个按钮内边距令牌，不允许现写像素值。**

```
--space-1:4  --space-2:8   --space-3:12  --space-4:16  --space-5:20
--space-6:24 --space-8:32  --space-10:40 --space-16:64
--button-pad-sm: 4px 12px   --button-pad-md: 8px 16px   --button-pad-lg: 12px 24px
```

> 历史问题：按钮内边距曾有三套各自硬编码的值（`7px 16px` / `5px 14px` / `10px 28px`）。

### 4.2 圆角

**`[约束]` 只用这 8 个，**唯一允许的字面值是 `50%`**（正圆）。**

```
--radius-none: 0   --radius-xs: 4px    --radius-fingerprint: 1px 1px 0 0
--radius-sm: 6px   --radius-md: 10px   --radius-lg: 16px
--radius-xl: 24px  --radius-full: 9999px
```

> 历史问题：曾出现 9 种圆角字面值，其中 `4px`、`50%`、`1px 1px 0 0` 没有对应令牌。
> `--radius-fingerprint` 专门给温度指纹柱用（顶部微圆、底部直角，让柱群连成一条基线）。

### 4.3 动效

```
--ease-out:      cubic-bezier(0.16, 1, 0.3, 1)      /* 出场：快进慢停 */
--ease-in-out:   cubic-bezier(0.65, 0, 0.35, 1)     /* 状态切换 */
--ease-spring:   cubic-bezier(0.25, 1, 0.3, 1)      /* 弹性：指示条 */
--duration-fast: 120ms   --duration-normal: 200ms
--duration-slow: 260ms   --duration-glacial: 700ms
```

### 4.4 层级

```
--z-bg: 0   --z-content: 1   --z-sticky: 10   --z-dropdown: 20   --z-modal: 40
```

**`[约束]` 3D 氛围层在 `--z-bg`，内容在 `--z-content`，二者是 `body` 下的兄弟节点。**
（`#atmosphere` 与 `.ambient-glow` **不是** `.app` 的子节点 —— 这一点曾被误判，导致无谓改动。）

**`[约束]` 高度（elevation）用 `--elev-*`（= 阴影令牌），不用 `filter: drop-shadow`。**

## 5. 内容宽度

**`[约束]` 只有两档宽度，按内容类型选，不看页面。**

| 令牌           | 值       | 用于                                                                     |
| -------------- | -------- | ------------------------------------------------------------------------ |
| `--width-data` | `1208px` | **数据型**：天气主页（多栏/图表/列表）、已登录的收藏与历史列表、指南内容 |
| `--width-form` | `400px`  | **表单型**：登录/注册、聊天输入区、指南空态                              |

**判定依据**：内容是"**可以横向扫描的**"（列表、多列、图表）→ `--width-data`；
内容是"**逐项填写的**"（输入框、按钮）→ `--width-form`。

**`[约束]` 表单控件可用宽度不应超过约 480px。** 超宽会让"光标到行尾"距离过远。

**`[约束]` 导航与内容必须对齐**：左侧竖排导航的定位必须由 `--width-data` 推导
（`left: max(16px, calc(50% - (var(--width-data) / 2)))`），**不得写死 `50% - 640px` 这类魔数**。
（历史问题：照 1280 的一半写成 640，而 `--width-data` 是 1208 → 导航永远偏左 36px。）

## 6. 数据可视化的视觉语言

**这是本项目最核心的视觉资产，不要随意改动。**

### 6.1 指标带（`.stats-scroll`）

**`[约束]` 三条同时成立：**

1. **上下各一条 1px 发丝线**（`::before` / `::after` 用 `--border`），**无外框、无圆角**
2. **显式列数**，禁止 `auto-fit`（会产生不等宽行 —— 这正是"空一块挤一块"的来源）
3. **骨架屏 `.skeleton-stats` 与真实带 `.stats-scroll` 必须用同一条选择器、同一组列数**

```css
/* 当前实现：两个选择器合并在一条规则里 —— 结构上不可能再分叉 */
@media (max-width: 599px) { .stats-scroll, .skeleton-stats { grid-template-columns: repeat(5, minmax(0, 1fr)); } }
@media (min-width: 600px) and (max-width: 839px) { … repeat(5, …) }
@media (min-width: 840px) { … repeat(10, …) }   /* 10 项一字排开 */
```

**`[约束]` 骨架屏的占位元素数量必须等于真实元素数量**（当前 10）。
**`[约束]` 该不变量必须由脚本断言**（`evidence/TASK-014b/skeleton-parity.cjs`），不靠人记得。

### 6.2 24 小时趋势曲线

- **只画"今天"的 24 个点**，X 轴 `00:00 → 23:00`
- 线用 `--primary`，面积填充用 `--primary` 的**低 alpha 线性渐变**（顶部实、底部透明）
- 曲线用 `bezierCurveTo` 平滑，**不是折线**
- 轴标签用 `--ink-secondary`，`tabular-nums`

**`[约束]` 数据源是 `hourly` 的**前 24 项**，必须显式切片。**
（历史 P0 级问题：后端曾返回 168 点、前端未切片 → 画出 7 个重复波峰。）

### 6.3 温度指纹（7 天预报的行内图形）

每天一行，用 **24 根竖柱**表示当天 24 小时的温度分布：

- 柱高 = `max(3, (v − scaleLo) / span × 48)px`，**用全周共享的绝对刻度**（不是每天各自归一化）
- 柱色 = `tempColor(v)`（§2.4）
- 轴刻度 `0 / 6 / 12 / 18 / 23`
- 右侧附 `最低 ~ 最高` 与 `中位 · 温差`
- 底边**共用一条基线**（靠 `--radius-fingerprint` 的直角底实现）

**`[约束]` 7 行都要有指纹；缺少数据时显示"温度指纹暂无"，不得静默留空。**
**`[约束]` 数据不足 24 点时必须返回空串**（不做近似），由调用方给兜底文案。

### 6.4 发丝线作为分隔

**`[约束]` 分隔用 1px 的 `--border`，不用阴影、不用间距硬撑。**
表格、指标带、日列表、危险区都靠发丝线组织。**`[决策]` 表格不用斑马纹。**

### 6.5 颜色不是唯一信息载体

**`[约束]` 任何靠颜色表达强弱的图形，都必须同时给出数字或文字。**
例：热门城市横条旁必须有次数；温度指纹旁必须有最低/最高/中位/温差。

**`[决策]` `clearNight()` 使用饱满的实心月牙，右上方配一大一小两颗四芒星。**

## 7. 动效原则

**`[约束]` 动效必须响应 `prefers-reduced-motion: reduce`**（3D 场景、粒子、过渡）。
判定方式：`window.matchMedia('(prefers-reduced-motion: reduce)').matches`。

**`[决策]`"强度靠长度，不靠数量"** —— 表达天气强度时，优先增加雨丝/雪花的**长度**与**速度**，
而不是把粒子数量翻倍。数量上去会直接变成"一堵墙"，也是"眩晕/头晕"反馈的来源。

**`[约束]` 禁止在 `update()` 里每帧重掷位置。** 粒子的位置分量必须在构建时存进 `data`
并在帧间复用；需要纵深变化时用**逐粒固定相位**做缓慢往复。

> **依据（实证）**：`RainScene` 曾每帧重掷 `z`，导致每个雨滴在深度方向每秒乱跳 60 次。
> 作者反馈"雨点特别急促" —— **而实测雨滴跨屏需要 41–90 秒，它其实几乎不动**。
> 症状与原因完全相反。修法是存 `z`，不是"放慢速度"。

**`[约束]` 禁止编排式的入场序列。** 不要"先淡入标题、再淡入卡片、再淡入图表"。
页面加载后应尽快可读。

**`[决策]` 装饰性动效必须低存在感** —— 例：亮色主题下的 3D 月亮是含蓄的浅灰圆盘，
不与天气图标争注意力（**图标是信息，装饰是装饰**）。

## 8. 反模式清单

**以下每一条都真实发生过，并有证据留档。新代码不得重犯。**

| #   | 反模式                                                 | 为什么错                                                                      | 正确做法                                                          |
| --- | ------------------------------------------------------ | ----------------------------------------------------------------------------- | ----------------------------------------------------------------- |
| 1   | **`auto-fit` / `auto-fill` 栅格**                      | 行宽不等 → "空一块挤一块"                                                     | 显式 `repeat(N, minmax(0, 1fr))`                                  |
| 2   | **`index.html` 里的内联 `<style>`**                    | 成为第二套样式来源，用 ID 选择器静默压过 `style.css`；只读 CSS 会得到错误答案 | 样式一律在 `style.css`；CSS 单一来源                              |
| 3   | **定义了不用的令牌**                                   | 误导后来者，且掩盖真问题                                                      | 每个令牌要么被 `var()` 用到，要么删掉                             |
| 4   | **断言里写死派生数量**（"8 个指标格"、"7 行"）         | 产品演进后必然失效                                                            | 与真实来源比对（`spans === chips`）或动态取数                     |
| 5   | **适配器改写被测脚本的断言**                           | 等于改了测试；失效被藏起来，比失败更糟                                        | 适配器只允许改运行时输出/路径/时序                                |
| 6   | **脚本里硬编码资源版本串**（`main.js?v=13`）           | 018b 改为内容哈希注入后全部失效                                               | 先抓页面再解析实际 URL，或按属性结构化匹配                        |
| 7   | **骨架屏与真实组件参数不一致**                         | 加载完出现布局跳动                                                            | 同一条选择器、同一组数值；脚本断言相等                            |
| 8   | **跨主题混用**（亮色卡片 + 深色场景底）                | 「浅色卡片浮在深色夜空上」                                                    | 亮色全亮、深色全深，不允许例外                                    |
| 9   | **用中灰底色配深色主题文字**                           | 对比度掉到 3.11:1 / 2.45:1                                                    | 深色主题所有场景底色都保持深色                                    |
| 10  | **`@media` 用 `--window-size` 伪装小视口**             | Windows 最小窗口 ~522px，`--window-size=375` 实际得到 492px；媒体查询没生效   | CDP `Emulation.setDeviceMetricsOverride`，并**断言 `innerWidth`** |
| 11  | **用 `documentElement.scrollWidth` 测横向溢出**        | `overflow-x: hidden` 会钳制它，断言恒真                                       | 用 `document.body.scrollWidth`                                    |
| 12  | **靠截图判断动效**                                     | 静态帧看不出闪烁/抖动                                                         | 用**连续帧**（改前 vs 改后）                                      |
| 13  | **"存在"当成"可用"**（加了 `tabindex` 就当可键盘操作） | 从未被真正使用过                                                              | 真实输入事件驱动的测试（`page.keyboard.press`）                   |
| 14  | **`font` 简写里带 `letter-spacing`**                   | `font` 不接受字距，写了会被忽略                                               | 字距单独用 `letter-spacing`                                       |
| 15  | **多处定义同一属性且值冲突**                           | 读其中一个来源会得到错误结论                                                  | 一处定义；冲突时合并成每档一条规则                                |

## 10. 如何修改本设计系统

1. **改任何 `[约束]` 项** → 必须给出**客观依据**（对比度实测、可复现问题、反例实验）
2. **改任何 `[决策]` 项** → 必须写明**理由**，并同步更新本文
3. **新增令牌** → 同时给出：用途、取值依据、**至少一处 `var()` 使用**
4. **改完必须跑**：对比度脚本、`check:versions`、`check:evidence`、三档截图
5. **本文没写的视觉取值** → 视为未定义；先补进本文，再写进代码
